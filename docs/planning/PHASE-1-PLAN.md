## Stage B: initial plan

1. **B-018:** `Library.deleteProfile(id, pin, key)` verifies the target's PIN inside the deleting transaction; `AppState.deleteProfile(profile, pin)` asks for it with the existing PIN pad.
2. **B-031:** call `setlocale(LC_NUMERIC, "C")` at the top of `main()` on Linux.
3. **B-001:** `key(player)` around `AndroidView`, so a new engine gets a new `SurfaceView`.
4. **B-026:** investigate; document.
5. **B-003:** a `source_endpoint` join table (migration 8): source ↔ endpoints with order, last success, last failure; the adapter is given the list.
6. **B-033:** a "Remove from favorites" on the `Gone` page.
7. **B-024:** show `W × H · codec · range` everywhere instead of resolution classes.
8. **B-005:** a status strip reserved under the top bar on every form factor.
9. **B-006:** an index for title search.
10. **Telemetry:** adopt a hosted analytics SDK with an opt-in switch.
11. **Baselines:** Macrobenchmark module on Android; a desktop start-up timer.

## Stage C: critique

1. **B-018: a PIN on deletion is weaker than it looks.** "Forgot PIN" already lets anyone erase a protected profile's private data without the PIN; deletion only adds removing the empty profile row. The real value of the fix is that destruction now needs either the PIN or the explicit, labelled "Forgot PIN" reset, never a casual Confirm, and that a wrong guess counts towards the lockout. Changing Forgot PIN would remove PIN recovery, which is the owner's call: recorded as an owner decision, not changed here. Also: authorising only in the library is too late, because AppState signs accounts out and deletes downloads *before* calling it, and verifying twice must not double-count a failure.
2. **B-031: once at `main()` is not enough if AWT sets the locale later**, and "do not switch around individual calls" must not become "never correct it". Measure whether the locale changes after the window and input method exist; if it does, also ensure it under the creation lock (a check that writes only when it differs). And `isAvailable` must reflect initialisability, or the UI keeps offering Play.
3. **B-001: `key(player)` alone fixes the A→B case, but the SurfaceView's lifecycle changes too.** The M10 continuity contract (one surface for a *playback* across full player, dock, and PiP) must still hold, since the key changes only with the engine. Attachment should not live only in `factory` either: an effect keyed on (player, view) makes it robust to any node reuse.
4. **B-003: a join table duplicates what the adapter must hold anyway.** Selection happens per request inside the adapter, which cannot read the database, so the address list must reach it through its config; a table *and* a config list are two truths that can disagree. Per-endpoint "last success / last failure" written to the database on every failover would also be a write per network blip (and the config is sealed: rewriting it is a credential-store write). Better: the ordered address list is part of the sealed connection (one truth, migrated by decoding old configs as one-address lists: no SQL migration, nothing to lose); runtime health is in memory; the shared `server_endpoint` rows stay what they are (addresses other profiles can pick). Also: the second sign-in must not create a second server session; it should *add an address* to the existing connection using its token, with a sign-in only if the token is refused there.
5. **B-024: replacing every label with `3840 × 2160` is a redesign during a beta**, and a 3840×1600 scope film *is* 4K by every convention the rest of the UI uses. The defect is the contradiction: a resolution or range written in a server's version name being presented as an edition. Fix the authority (probe > server's stream facts > file-name hints; a name made only of quality tokens is not an edition) and show exact dimensions where people look at technical detail (the version's technical line), not on every badge.
6. **B-005: a strip reserved on every form factor costs every page height** on phones and televisions, where vertical space is scarcest, to show something transient. Better: where the top row has room reserved (rail, sidebar) keep the label; where it does not (phone, television), show the dot alone in its fixed place, with the label given to screen readers and shown in full on Sources.
7. **B-006: an index is speculative until measured.** The likely cost is rebuilding the whole document set per keystroke and per revision, not SQL. Measure first.
8. **Telemetry: an SDK is the wrong first step.** Most collect device, session, and locale data automatically; PostHog and Firebase do a lot by default; none is needed to send a handful of enum events. And an opt-in switch with no approved endpoint would claim sharing that does not happen. Better: Reflux's own allow-listed schema, consent, and transport interface, with transmission compiled out (no endpoint) until the owner approves a provider; the switch appears only in a build that has one.
9. **Baselines: a Macrobenchmark module is a new build module, a new AndroidX dependency, and a new benchmark build type** in a fix season, and no V1 decision waits on it. A small instrumented start-up measurement through `am start -W` and the existing on-device test harness answers the same questions on two real devices; Macrobenchmark is recommended for M12's campaign with its cost stated.

## Workstream 12 (added by the owner, 2026-11-18): libmpv in the Linux tarball

Research: the tarball has no libmpv and needs the distribution's; Windows ships Reflux's own LGPL build (tools/libmpv) because Reflux is proprietary. Copying the distribution's libmpv was ruled out at once (Ubuntu's mpv and FFmpeg are GPL builds). The plan was an LGPL build for Linux from the same pinned sources on an old glibc base, with only system libraries for drivers, display, and audio, loaded by absolute path with the system's as the fallback. **Critique, from the source:** mpv 0.42.0's `meson.build` makes X11 GPL-only (`x11` requires `gpl`; `x11_common.c`, `vo_x11.c`; `gl-x11`, `egl-x11`, `vdpau`, `vaapi-x11` follow it), and Reflux's Linux player is an X11 window (`wid`). An LGPL libmpv cannot show video in Reflux on Linux. **Re-plan:** no bundling (it would either not work or not be LGPL); keep the distribution's libmpv and name the exact package per distribution in the app; verify each command in a clean container with the packaged tarball; record the real route (mpv's render API with Reflux owning the GL surface) as an owner decision. DECISIONS.md, 2026-11-18.
